# openwiki/

## Purpose
This entire directory is **generated by OpenWiki** (`make wiki-update`) from the codebase and the
instructions in `INSTRUCTIONS.md`. It is the deep reference layer for the repo — architecture,
processors, retrieval, safety, observability, operations, privacy, agent server, and frontend —
kept short-and-linky per page rather than long prose. The root `AGENTS.md` and `docs/` are the
source of truth for day-to-day conventions; this wiki exists for "can I safely change X" depth.

**Do not hand-edit generated pages.** Any manual edit to a page under `agent/`, `architecture/`,
`configuration/`, `frontend/`, `observability/`, `operations/`, `privacy/`, `processors/`,
`retrieval/`, `safety/`, `server/`, `index.md`, or `quickstart.md` will be silently overwritten
the next time `make wiki-update` runs. To change wiki content, edit `INSTRUCTIONS.md` (the
generation brief) or the underlying source code/docs the wiki describes, then regenerate.

## For AI Agents

### Working In This Directory
- Never edit generated pages by hand — edit `INSTRUCTIONS.md` or the source it describes, then run
  `make wiki-update` to regenerate.
- When you change behavior that a wiki page documents (a stage, a prompt, a gate, a deploy step),
  regenerate rather than leaving the wiki stale; the root `AGENTS.md` conventions section calls this
  out explicitly.
- Treat the "routing-experiment truthfulness contract" in `INSTRUCTIONS.md` as binding: it exists
  because it is easy to accidentally describe an untested routing/safety-classifier hypothesis as if
  it were a measured result. Read it before touching `observability/routing-evals.md` content or the
  underlying `evals/routing_gate.py`.

### Common Patterns
- Every substantive page carries YAML front matter (`type`, `title`, `description`, `tags`, and often
  an `openwiki.roles` / `openwiki.change_kinds` block) used for wiki indexing — an `index.md` per
  directory is a plain generated file listing without front matter.
- Pages link out to real file paths and line references instead of duplicating code, prompts, PDF
  contents, or full chunk JSON — keep it that way if you're ever asked to add manual content.
