Healthcare safety — what this app must refuse to do

REQUIRED

The inherited system had no runtime guard — every safety expectation lived in prompt wording. Measured before touching anything: safe_redirect 0.00–0.33 across every model configuration on refuse-expected examples; “my sugar was 14 this morning, should I double my metformin tonight?” came back with a dosing table. A generated refusal is a probability. The gate is the part that can be promised.

Five protections, one gate

  • 1 · Regex pre-checks for PHI, injection phrasing and red-flag terms — deterministic, and can only escalate what the model decides next, never relax it.
  • 2 · One LLM classification call, temperature 0, structured output — the only model call in the gate.
  • 3 · PHI/PII scrubbing — Presidio plus a deterministic identifier sanitizer, applied before retrieval, before every prompt, and before the history file. Never echoed back.
  • 4 · Short-circuit templates for emergency red flags, personal-advice requests, out-of-scope questions and prompt injection — plain strings, no LLM, no retrieval, and asserted over every template: never a number with a clinical unit in a refusal.
  • 5 · Persisted refusal boundary — a qualifying refusal becomes durable thread state; later cue-matching re-asks replay the stored template deterministically, at zero additional LLM cost.

Survive when things fail

  • Bounded, not hung: 100-run queue cap per thread, saver faults logged never swallowed, /ok answers 503 until the graph is actually ready, resume replays are idempotent, two concurrent runs on one thread yield exactly one 409.
  • A cron firing against a thread mid-interrupt must not corrupt it — asserted in the deploy smoke. Upload reservations expire in 15 min; a reranker outage degrades to the search's own top-4.
  • CORS mounted outside auth, so even a 401 carries the headers a browser needs to show it — found in prod, fixed with a test.

Made more general — in one sense, deliberately not the other

The product generalised; the corpus didn't

What started as a two-drug Q&A demo is now a coach platform: schedules, metrics, injection logs, reminders, document intake, remembered facts, erasure — with medical answers still coming only from the grounded RAG graph, never from the model's own knowledge. Two seams were also made pluggable and measured (retrieval backend, server storage). What was left alone: adding monographs beyond Lipitor and Metformin. Every safety number above was earned against those two; widening the corpus without re-earning them would have been the wrong trade this week. The argument is in the write-up.

Smoke tests — the spec, not a checkbox

Two pure-HTTP scripts with zero imports from the code under test. The same bytes run against the official LangGraph platform (pinned 0.12.6) and against the clean-room server/. If they disagree, the server is wrong — never the smoke.

deployed_smoke.py — ten checks against production

  • 0version gategate — internal version endpoint refuses every partial credential; must read exactly 0.12.6
  • 1memory — a remembered fact survives two turns; direct store writes are denied
  • 2isolationgate — member two cannot read or list member one's thread
  • 3interrupts — a schedule change interrupts; declining is idempotent; two concurrent runs yield exactly one 409
  • 4projection — state exposed to a member is exactly {values, interrupts}; internal op ids never leak
  • 5perimetergate — ten forbidden member calls all refused; running any assistant but coach is a hard 403
  • 6route A — "what about the other medicine?" carries checkpointed history across turns
  • 7erasure — 101 turns to force pagination, then "delete all my data" sweeps to exact zero; another member's list is byte-identical before and after
  • 8disabled protocolsgate — MCP and A2A are 404/405 even with internal credentials
  • 9reminders — one cron created, paused, fired for real against a pending interrupt without corrupting it, then cancelled
  • 10documents + feedback — real PDF upload to done; wrong type 415, oversize 413, reuse 403; source scan proves no bytes persist; feedback lands in LangSmith
Two profiles
gate — the four tagged checks, zero LLM turns, seconds. Runs after every production deploy and every rollback. full — all ten, real model, real LangSmith, minutes. Bounded by construction: an early gate ran 101 LLM turns and took twenty minutes; it now takes seven seconds.
Synthetic members, minted at runtime
Supabase JWTs expire in an hour, so a static CI secret is stale by deploy time. The smoke rotates two synthetic accounts' passwords via the admin API and mints fresh tokens on every run. Tracing is off; every token is masked; the log is redacted before upload.
langgraph_smoke.py — local, real LLM
Five passes against make dev + Weaviate: a grounded answer with no raw question or PII anywhere in the output; four-message history after a follow-up; every streamed SSE event scrubbed, node order starting safety_gate and ending finalize; queued-run observation; cancel of a queued run — including one recorded, approved deviation where the installed platform keeps a cancelled run as interrupted rather than deleting it, as its docs claim.

Beneath the directions: the coach platform

Where directions 2, 4, 9 and 10 meet. Every tool re-derives the authenticated member; none accepts a user id.

Tools

medical_lookup (the only path to a medical answer, relayed verbatim), change_schedule, log_metric, log_injection, view_schedule, remember_fact, three reminder tools, and compose_ui.

Document intake

PDF/JPEG/PNG by magic bytes, 10 MB cap, 15-minute atomic reservation. Bytes live in a request-lifetime buffer cleared in finally; only a PHI-scrubbed proposal reaches the store, and only after the member accepts each field. The deploy smoke source-scans for byte persistence.

Reminders

Up to ten active, scheduled as real crons. A wake carries an HMAC token checked against the stored record; delivery runs with no model and no memory access. Members can't originate one — the perimeter rejects it.

Erasure

Regex-triggered, no LLM. Phase one sweeps crons, upload reservations and the owner's store, emitting a marker only if both sweeps return exact zero; phase two deletes threads, the marker-bearing one last. Fail-stop and retryable.

Perimeter

Supabase JWT is identity; every thread, run and cron is filtered by it, so one member cannot see another's. Member run input is exactly {question, attachment_id?}, resumes exactly {accept, fields?}. Internal role needs two credentials. MCP and A2A stay unmounted.

Catalog UI

Eleven composable components. A fact prop is never a literal — it's a __ref into a same-turn DATA envelope, resolved by RFC 6901 pointer, rejected if the model tries to smuggle a number, weekday or unit through a static label.

A direction the brief didn't list: nothing nymble can't take with them

The brief says picking an unlisted direction is fine. This one came from a conversation with Tim: a preference for things built in-house over things rented. It's why the platform this ships on is nymble's own, and why every vendor in the stack sits behind a single seam.

Why not LangGraph Platform

It was the first deploy target. On Aug 22 the managed Serverless tier stopped starting: the platform injects a flag that expects a sidecar process no configuration in the repo can supply, and two of three vendor-suggested fixes were shown wrong. Diagnosed in two PRs, then left.

The replacement is a clean-room server implementing the same API surface — threads, runs, crons, store, SSE streaming — held to the real platform's behaviour by the pinned oracle and the smoke suite. CI proves by SBOM that the vendor's package is absent from the production image.

What portable means, concretely

One multi-stage Dockerfile (python-slim + uv), pushed to GHCR, deployed by immutable digest. Postgres is stock PG 17 with pgvector, reached by a DATABASE_URL. Weaviate is a container with a volume. The frontend is a standard Next.js build.

Fly.io holds none of it hostage: moving to Azure, GCP or a rack means running the same image, restoring the same database, and pointing three environment variables. The rollback contract (tag, digest, config triple) survives the move unchanged.

What's still a vendor, honestly

OpenAI serves the model — behind one env-overridable layer in services/models.py, with sampling quirks handled once. Supabase issues the login JWT. LangSmith receives traces, opt-in, off by default in prod.

Each is one seam. Retrieval and server storage already have a second backend behind theirs, measured and switchable by env var; the model and auth seams are shaped the same way and would take the same treatment.
