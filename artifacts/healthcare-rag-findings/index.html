The result, before the journey

Accuracy alone did not decide what to ship.

In healthcare the best system is the one that answers well, cites the monograph, costs something sane, and refuses when it should. Over three days the demo became a LangGraph runtime that holds that line. Three retrieval alternatives were then measured against it and turned down.

01

The assignment shaped the lens

Safety was required. Measurement made the judgment defensible.

The brief asked for healthcare restraint first, then two or three deliberate directions, and for an account of what was left alone and why. I picked the two that make the first one checkable. Each quote below links to the page of the assignment PDF it comes from.

Direction 4 · required

"Take the healthcare context seriously. There are things this app should not do, data it should not touch, cases it should not answer. Figure out what those are and enforce them."Brief, page 1, direction 4

Decide what the assistant refuses, what data it must not keep, and when it redirects. Then enforce that in the runtime, not in a prompt.

Direction 3 · measure

"Make it possible to know whether a change made things better or worse. Give it a safety net for regressions."Brief, page 1, direction 3

A regression net: 86 single-turn and 22 multi-turn cases, judged for correctness, grounding, retrieval, safety, latency and cost, with the reports committed.

Direction 5 · question the shape

"Question the approach itself. The framework, the orchestration, the pipeline shape, none of it is sacred. If there's a simpler or better way to do this job, build that."Brief, page 1, direction 5

Replace speculative sub-answer selection with synthesis, move the runtime to LangGraph, then put PageIndex, Pinecone and a reranker through the same judge.

05

What graph-final consists of

A safety-first graph, with bounded work and one synthesized answer.

Luna runs the main stages, Terra validates citations, and Weaviate supplies hybrid retrieval over the two monographs.

  1. Safety gateScrub PHI, classify, and short-circuit emergencies, personal advice, out-of-scope requests and instruction overrides.
  2. Clarify + conversation contextRun in parallel, using scrubbed checkpointed history.
  3. Complex-only decompositionAlways keep the parent query. Add at most three evidence-gathering subqueries.
  4. Hybrid retrieval + mergeSearch Lipitor and Metformin, then deduplicate by document ID.
  5. Retrieval evaluationAllow one bounded gap-fill round when evidence is thin.
  6. Generate onceAnswer the original question over the merged evidence.
  7. Validate + follow upStructure citations with Terra. Generate follow-ups only for validated answers.
  8. FinalizePersist only the scrubbed conversation pair and return graph telemetry.

Short-circuit path

Refusals return deterministic templates without retrieval or answer generation. Follow-ups are empty.

Synthesis is implicit

There is no "pick the best sub-answer" stage. Every retrieval branch merges before one generation call.

Configuration

gpt-5.6-luna main · gpt-5.6-terra validator · reasoning effort none · all stages enabled.

Why LangGraph, beyond parity

Decision D10 lists three reasons. The graph had to match the gated pipeline before it could replace it. Its checkpointer already carries per-thread conversation memory (in memory by default, SQLite with HC_RAG_CHECKPOINT) and is the natural seat for long-term memory later. And langgraph dev brings Studio, thread inspection, streaming and cancel/rollback, which is most of the developer experience the brief's directions 1 and 6 ask for.

Multi-turn pressure

A refusal now persists across turns. Safety drift fell from 0.41 to 0.27.

graph-final multiturn-graph-final-a7e609e7 → boundary-persisted boundary-on-r4-aeb73d36

Graph-final classified every turn on its own, so a pressure campaign was a series of independent coin flips: the refusal that held on turn one said nothing to the turn-three classifier. The persisted refusal boundary stores a qualifying refusal in the thread's checkpoint and replays it byte-identically, with zero LLM calls, when the same ask comes back in new clothes.

What I would still watch

n is 22 conversations and the 95% interval on drift runs from 0.09 to 0.46, so this is a clear direction, not a tight number. The failure mode to fear is the opposite one: an over-eager boundary refusing a legitimate follow-up. An informational override sends document-sourced wording ("per the monograph...") back through the full gate, and conversations mt-017 to mt-021 pin that behaviour. Stored boundaries only ever escalate; none is relaxed mid-thread.

The LangGraph StateGraph is now the only runtime. A sanitizer the process owns (Presidio 2.2.364, spaCy en_core_web_sm, deterministic CA/US healthcare-ID patterns) scrubs identifiers before any model sees them.

  1. Scrub before classificationIdentifiers leave the query and history before the safety gate runs, and stay scrubbed even when the gate is ablated.
  2. Sanitize at every sinkEvery model-authored query is scrubbed at its next sink. Answers and follow-ups are scrubbed again at finalize.

11

Questioning the retriever

Three retrieval alternatives went through the same judge. All three lost.

It would have been easy to swap in a fashionable retriever and call it an upgrade. Instead each one ran behind a knob, against a fresh Weaviate reference in the same session, with the pass marks fixed before the first number came in. Only the retrieval stage differed; the safety gate, decomposition, generation and validation stayed byte-identical on every arm.

Stage 1 · retrieval only

71 golden questions, route and search on every arm, no generation. Page recall with the harness's own definition. About 3 minutes per arm.

Lose page recall? Out.

A retriever that returns worse pages cannot be rescued downstream, so no judge budget is spent on it.

Stage 2 · paired, judged

Best passer versus a fresh reference: core and holdout, 2 repetitions, n = 172 per arm. Correctness must rise 0.03 with groundedness, holdout, cost and p50 held.

Frozen before results

Thresholds written into a spec first, then a self-check with identical arms (Δ = 0.000). The reference drifts ±0.02 between runs, so unpaired comparisons were never allowed.

Right pages, thinner chunks. In the full pipeline page recall was flat (0.680 to 0.690) while chunk recall fell 0.657 to 0.639 and must-mention recall fell 0.603 to 0.568. The reranker prefers chunks from the right page that carry fewer of the facts the answer needs. Paired per question: 4 wins, 11 losses, 44 ties. Cost was +3% and p50 +7%, both inside the 1.25× gates. Quality is what failed.

Why PageIndex lost

79 pages across two monographs; its benchmarks are on thousand-page filings. Its local mode has no retrieval call at all (only submit, get_tree, get_ocr), so the one-call node selector was ours, and it doubled retrieval latency.

Why Pinecone lost, as configured

Same embedding model, same chunks. A dense-only diagnostic scored −0.057, so about 0.13 of the 0.185 loss was my fusion: a convex mix of raw dot-product and raw sparse scores, where Weaviate normalises each ranking first. Not tuned after the fact. The decision record names normalised fusion as the way to reopen it.

What was kept, and why that is an answer

Weaviate hybrid search exactly as inherited: limit 4, alpha 0.65, relative-score fusion. The brief asks what was deliberately left alone and why (page 1); this is the measured version of that answer. Every arm stays in the repo behind knobs that default off, and the gate runs any new retrieval idea in about 15 minutes, which is the "eval loop your tool could call" the brief asks for on page 2.

12

Shipped state

One runtime, privacy scrubbed in process, a boundary that holds, retrieval left alone on evidence.

The release code is the graph and only the graph. Journey T21 to T26, decisions D01 to D17 and findings F25 to F42 record how each claim was earned. Both parity tags are pushed and every number below maps to a committed report.

01

The shipped surface

Correctness 0.853 vs legacy 0.813, answered 1.00, zero pipeline errors. Best multi-turn graph run: turn correctness 0.807, consistency 0.818, self-contradiction 0.227, forbidden content 0.000.

02

The accepted cost

The validator is about 90% of pipeline spend and 5 s of p50, accepted as-is (D15). Without it, false-premise correction falls 1.0 → 0.875 and hallucinated rises 0.08. If cost ever matters, use a cheaper validator. Do not remove it.

03

The boundary

Safety drift 0.41 → 0.27 (median of 3 judge reruns), PII persistence 0.19 → 0.125, replay precision clean, with the knob HC_RAG_REFUSAL_BOUNDARY defaulting on. Still n = 22; I would rerun before quoting the number to anyone outside.

04

Retrieval

PageIndex, Pinecone and a reranker each lost to the inherited hybrid search under a frozen paired gate. Open: normalised fusion for Pinecone, and an alpha/limit sweep on Weaviate itself, both through evals/pageindex_gate.py. Rotate the Pinecone key.
