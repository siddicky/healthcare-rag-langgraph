# scripts/verify/

## Purpose
Four sequential gate checks (`f1`-`f4`) that verify a plan/change is complete,
correct, tested against a real environment, and scoped to what it claims to
touch — the kind of checks a release or PR-acceptance workflow runs before
declaring a plan "done". Named `f1`.."f4" rather than descriptively, matching
whatever numbered acceptance-plan convention this repo's release process
uses.

## Key Files
| File | Description |
|------|-------------|
| `f1_plan_compliance.py` | PEP 723 self-executing script (`--plan <plan> --evidence-dir <dir>`) that checks a plan document's claims against collected evidence in `<dir>`; uses `subprocess`/`re` to inspect the evidence and a `pydantic.BaseModel` to structure results. |
| `f2_quality.sh` | Runs `make test` and scoped `ruff check` (only over `healthcare_rag/agent`, `evals/agent_cases.py`, `evals/agent_chunks.py`, and the todo-16 agent-parity files under `evals/`) — deliberately does not lint the rest of the repo, which predates ruff adoption ("protected-dirs principle: no retroactive grading of untouched code"). Reports PASS/FAIL per stage via `run_stage()`, accumulates a nonzero exit if any stage fails. |
| `f3_realenv.sh` | Requires `LANGGRAPH_DEPLOYMENT_URL` and `DEPLOYED_URL` (fails fast if unset); runs `scripts/deployed_smoke.py --url "$LANGGRAPH_DEPLOYMENT_URL"`, then drives a Playwright config against the deployed frontend using Supabase member credentials (`SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, plus member email/password) via a generated temp config under `frontend/e2e/.tmp/`. |
| `f4_scope.sh` | Diff-based scope gate: reads `BASE_SHA` from `${EVIDENCE_DIR:-.omo/evidence}/BASE_SHA`, then fails if `healthcare_rag/graph/` or `healthcare_rag/processors/` (the "protected directories") changed since that SHA or are dirty in the worktree/index. Also greps for `cron_client` imports outside the internal-only modules (`cron_client.py`/`reminders.py`) in `healthcare_rag/agent`. |

## For AI Agents

### Working In This Directory
- `f4_scope.sh`'s protected-directory list (`healthcare_rag/graph/`, `healthcare_rag/processors/`) is a policy statement, not an accident — a plan that legitimately needs to touch those directories must update this list deliberately (and get that reviewed), not work around the check.
- These scripts assume `git` operations run with `GIT_MASTER=1` set (see the `git diff` invocations in `f4_scope.sh`) — an env convention used elsewhere in this repo's git-touching tooling; don't drop it when copying the pattern.
- `f2_quality.sh`'s ruff scope is intentionally narrow; don't widen it to "the whole repo" without a separate decision to adopt ruff repo-wide.
- All four are meant to run in sequence as gates (f1 → f2 → f3 → f4), each independently exitable with a nonzero code on failure — keep that contract (clear PASS/FAIL stderr/stdout and a meaningful exit code) if you add an `f5`.

### Testing Requirements
- These scripts are the tests/gates themselves; there is no meta-test suite for them beyond running them against a real evidence directory and deployment.

### Common Patterns
- `set -euo pipefail` (or `set -uo pipefail` in `f2_quality.sh`, which accumulates failures instead of exiting on the first) at the top of every shell script.
- Fail-fast argument/env validation with actionable stderr messages before doing any real work.
