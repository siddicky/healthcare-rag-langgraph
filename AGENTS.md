# AGENTS.md — working on healthcare-rag

Guidance for humans and AI coding agents. Keep it short and true; the deep
docs live in `openwiki/` (generated) and `evals/README.md`.

## What this is
A RAG assistant that answers questions grounded in two drug monographs
(Lipitor, Metformin). Weaviate hybrid search → OpenAI generation → citation
validation, orchestrated speculatively (`healthcare_rag/orch/`). Entry: `python -m healthcare_rag`.

## Setup (5 minutes)
```
cp .env.example .env            # add OPENAI_API_KEY (+ LANGSMITH_API_KEY)
make venv                       # uv, Python 3.12, editable install
make weaviate ingest            # docker compose + load data/chunks_*.json
make run                        # interactive CLI
```
Python **≥3.11** is required (`typing.Self`). Do not use `requirements.txt` —
its pins are mutually incompatible; `pyproject.toml` is the dependency source.

## Non-negotiables
- **Healthcare context.** The app must not give personal medical advice, must
  not answer outside the monographs, must not echo PII. This is enforced at
  runtime by the **safety gate** (see below), not just asked for in prompts. Any
  change to prompts, models, retrieval or orchestration must be checked against
  the safety categories in `evals/golden_dataset.json` (`unsafe_personal_advice`,
  `pii_or_phi`, `out_of_scope`, `adversarial_hallucination`) and the multi-turn
  ones (`safety_drift`, `pii_persistence`, `escalation`).
- **Measure before/after.** Run `make eval PREFIX=<change>` and compare with the
  previous report in `evals/results/`. Don't claim an improvement without it.
- **Secrets only in `.env`** (gitignored). Never commit keys; never print them.
- **Model selection is centralised** in `healthcare_rag/services/models.py`
  (env-overridable). GPT-5.x reasoning models reject `temperature` unless
  `reasoning_effort="none"` — always go through `sampling_params()`.

## Conventions
- Prompts are Jinja YAML in `prompts/`; the first line comment states the
  response model. Change prompt + Pydantic model together.
- Log through `logging.getLogger("MedicalRAG")`.
- Prefer small, reviewable PRs; each PR that touches behaviour links its eval
  report (`evals/results/<experiment>.md`) in the description.
- Regenerate the wiki after structural changes: `make wiki-update`.

## Safety gate (Direction 4)
Every query goes through `healthcare_rag/processors/safety.py` **before** anything
else — one classification call (~1.3 s, ~$0.0001) plus deterministic regex
pre-checks that can only escalate, never relax, what the model decided.

What it does:
- **Scrubs personal identifiers** (name, health card, MRN, DOB, address, postal
  code, phone, email) out of the query before retrieval, before any prompt, and
  before the conversation history file — and never echoes them back.
- **Short-circuits** with a plain-string template, no LLM and no retrieval, for
  `emergency_red_flag` (urgent-care redirect), `personal_medical_advice` (decline +
  who to ask), `out_of_scope` (what we cover instead), `prompt_injection` (the
  instructions don't change), and requests to recite identifiers back.
  Follow-ups are empty on a short-circuit.
- **Never puts a number with a clinical unit in a refusal.** Asserted over every
  template in `tests/test_safety_gate.py`.
- `in_scope_informational` / `ambiguous` go through the normal pipeline unchanged.

Knobs: `HC_RAG_SAFETY_GATE` (default true) or `HC_RAG_DISABLE_STAGES=safety` to run
un-gated for an ablation. Templates live in
`healthcare_rag/processors/safety_responses.py`; the classification prompt is
`prompts/safety_gate.yaml.j2`. The policy, the addendum rule and the known limits
are written up in **`docs/safety.md`** — read that before changing behaviour.

Measure it with `make eval PREFIX=<change>` and `make eval-multiturn PREFIX=<change>`,
then `make compare`. Per-query gate decisions land in the eval output under
`safety_outcome`. Safety metrics going up while `correctness` / `groundedness` /
`chunk_recall` stay flat is the bar; an over-eager classifier refusing answerable
questions is the failure mode to watch for.

## Known gotchas
- Weaviate compose uses `restart: on-failure:0`; if it exits cleanly it stays
  down — `make weaviate` again.
- Chunk ids are stored as `id_` in Weaviate (`id` is reserved).
- Validation (`validate_answer`) is by far the most expensive stage; look there
  first when optimising cost.
- Decomposition no longer answers per sub-query. Sub-branches (`decomposed_*`)
  stop after retrieve+evaluate; their documents are de-duplicated by `doc_id`
  into one `synthesized` branch that answers the **original** query once, and
  that branch outranks every other trait in `_select_best_answer`. Knobs:
  `HC_RAG_SYNTHESIS` (default true), `HC_RAG_MAX_SUBQUERIES` (default 3),
  `HC_RAG_DECOMPOSE_ONLY_COMPLEX` (default true) — see
  `healthcare_rag/services/models.py`. Set `HC_RAG_SYNTHESIS=false` to get the
  old per-sub-branch behaviour back for an ablation.
- The safety gate short-circuit returns `follow_ups == []` and sets
  `orchestrator.safety_outcome`; it also sets `monitor.raw_answer_event` (with no
  raw answer) so a UI waiting for a preliminary answer does not sit on its timeout.
- The decomposer is non-deterministic on borderline queries: the same question
  can come back `simple` on one call and `complex` with 4 sub-queries on the
  next, so branch counts vary run to run.
